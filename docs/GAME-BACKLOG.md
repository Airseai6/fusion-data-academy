# 数学小游戏 · 第二批需求（A1 提案，H2 实施）

> 目标：把「反直觉 · 抓狐狸」从一个单独小游戏，扩展成 **聚变数据学院的数学小游戏系列**。
> 每个 3–8 分钟、单文件 HTML、移动端可玩、无后端、有可解释的数学结论、可分享。
> 本文是 A1 的需求输入；H2 负责实现、测试、提交、发布；A1 负责验收。

## 0. 调研结论

同类产品可以分四类，值得借鉴的共性：**短局、每日一题、失败也能学到东西、结果可分享、零登录**。

| 类型 | 代表 | 可借鉴 |
|---|---|---|
| 每日数学猜谜 | [Nerdle](https://nerdlegame.com/)、[Mathler](https://www.mathler.com/)、[Math Wordle](https://apps.apple.com/na/app/math-wordle/id6762573910)、[Number Salad](https://play.google.com/store/apps/details?id=com.numbersalad.app) | 每日种子、6 次内、反馈颜色/符号、分享成绩、练习模式 |
| 经典猜数/推理 | Mastermind、Bulls & Cows；[Mastermind 教学研究](https://scholar.google.hr/citations?view_op=view_citation&hl=hr&user=bVPewS0AAAAJ&citation_for_view=bVPewS0AAAAJ:Tyk-4Ss8FVUC) | A/B 反馈、候选集、排除法、信息量提示 |
| 路径/围堵推理 | 经典「五个洞抓狐狸」谜题（[出处](https://miyucai.com/riddle/1895)）、Fox and Hounds | 当前抓狐狸的同类扩展：围堵、追逃、图上的必胜策略 |
| 经典数学谜题 | Nim、汉诺塔、15 数码、过河、24 点、天平称重、Monty Hall、数独/数织 | 规则一句话、策略可证明、可做难度梯度、可解释 |

**选题标准**：一句话能讲清规则；3 分钟内能玩一局；有明确数学概念；有“原来如此”的解释；单文件实现成本 ≤ 1 天。

## 1. 优先级与批次

### P0 · 第一批（先做 2 个，逐个提交）

#### G1《数字侦探 · Bulls & Cows》

- **数学概念**：信息论、排除法、候选集收缩。
- **规则**：系统生成 4 位数字（默认不重复；困难可重复），玩家 6 次猜测；每次反馈 `A`（数字和位置都对）与 `B`（数字对、位置错）。
- **交互**：数字键盘/输入框、历史列表、剩余次数、错误提示；结算页给出正确答案与一句策略解释（“优先猜能排除最多可能的数”）。
- **每日/练习**：每日种子（日期 hash）保证所有人同一题；练习模式随机。
- **验收**：
  - [ ] 6 次内可解；非法输入（长度/重复）有提示且不扣次数；
  - [ ] 反馈 A/B 计算正确（用确定样例断言）；
  - [ ] 每日种子同一天稳定；localStorage 记录当日结果；
  - [ ] 分享文案包含成绩与站点链接；
  - [ ] Playwright/CDP 测试：完整赢一局 + 输一局 + 刷新恢复。
- **文件**：`games/digits/index.html`（或 `puzzle/digits/`），在 `/puzzle/` 入口加卡片。

#### G2《最后一颗 · Nim 取子》

- **数学概念**：博弈论、必败态（P-position）、二进制异或。
- **规则**：3 堆石子（默认 3/4/5，可随机）；双方轮流从任意一堆取走至少 1 颗，取走最后一颗者胜（可切换“取最后者输”模式）。
- **AI**：三档难度；最高档必须走最优策略（异或为 0 时随机/诱导，非 0 时取到异或为 0）；AI 思考 300–600ms，避免瞬移。
- **交互**：点击堆取子（可选数量）、回合提示、悔棋（练习模式）、结算解释（“把每堆数量异或起来，让结果为 0 就是留给对手的必败态”）。
- **验收**：
  - [ ] 规则正确：取完/取最后判定；两种胜负模式都测；
  - [ ] 最高难度 AI 在任意初始局面不可被击败（脚本穷举或随机对局 100 局验证）；
  - [ ] 提示模式能显示每堆异或值；
  - [ ] 移动端单手可玩；结算有策略解释；
  - [ ] Playwright/CDP 测试：赢一局简单 AI、输一局困难 AI、模式切换。
- **文件**：`games/nim/index.html`，入口页加卡片。

## 2. 所有游戏共用要求

1. **单文件**：`games/<slug>/index.html`，内联 CSS/JS；除 `analytics.js` 外无外部依赖。
2. **移动端优先**：375×667 可完整操作；触控目标 ≥ 44px；不依赖 hover。
3. **视觉**：沿用现有深色 + 暖色点缀 + 纸张/仪表盘质感；标题用“反直觉 · XXX”系列命名。
4. **教学**：结算页必须有一段“数学解释”（≤80 字）和“再来一局/换难度”。
5. **数据**：`analytics.js` 事件：`game_start`、`game_win`、`game_fail`、`share`，带 `game` 与 `difficulty`。
6. **分享**：生成可复制的成绩文案（不含剧透答案），含站点链接。
7. **SEO/入口**：`<title>`、`meta description`；在 `/puzzle/` 与首页加入口卡片。
8. **测试**：每个游戏至少 3 条真实浏览器 E2E（赢/输/刷新），提交时附测试命令；A1 会用 live 页面复验。
9. **性能**：首屏 ≤100KB（不含分享图）、无控制台错误、无未捕获 Promise。

## 3. 交付节奏

1. H2 先实现 **G1**，独立 commit，并在房间回报：文件、测试命令、E2E 结果；
2. A1 在 live/本地复验，通过后 H2 再开 **G2**；
3. 两个 P0 上线后，A1 整理“系列首页”信息架构，再排 P1；
4. 每个游戏上线后更新 README 与 `/puzzle/` 入口。

## 4. 本批不做

- 后端排行榜、账号系统、付费墙；
- 多人实时对战；
- 复杂 3D/Canvas 物理（除非现有页面已复用）；
- 未经验收直接批量上线多个游戏。
